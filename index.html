Remote dd Clone: SATA to USB over SSH

● Probing local Docker backend…

Clone a running SATA disk from a remote host to a USB drive on this machine — or to a destination on another host — over SSH, with live progress. Two paths, same outcome: a downloadable script you can run by hand, or an interactive panel that unlocks when the local Docker backend is running.

Stop. dd writes raw bytes. If you point of= at the wrong device, that device's data is gone. Every command below has a verification step before any write. The backend refuses unlisted destinations and requires you to type the destination path verbatim.

Manual walkthrough (no Docker)

Same outcome as the interactive path, done by hand.

1Identify the source disk on the remote host
ssh user@source-host
lsblk -o NAME,SIZE,TYPE,MODEL,TRAN
sudo fdisk -l

Confirm the device name (e.g. /dev/sda). Check that TRAN is sata. Write it down.

2Identify the USB disk locally
lsblk -o NAME,SIZE,TYPE,MODEL,TRAN
sudo fdisk -l

Confirm the target device name (e.g. /dev/sdb). Triple-check it. Target size must be at least the source size.

3Unmount the target
lsblk /dev/sdb
for p in /dev/sdb*; do
  [ -e "$p" ] || continue
  if findmnt -n "$p" >/dev/null; then
    sudo umount "$p" || echo "umount failed for $p — check: lsof $p"
  fi
done
if mount | grep -q ' /dev/sdb'; then
  echo "STILL MOUNTED — do not proceed"
else
  echo "nothing mounted from sdb"
fi

If umount prints target is busy, the loop echoes the exact lsof command. Stop the holder before continuing.

4Dry run: SSH and sudo work
ssh user@source-host "sudo -n true && echo SUDO_OK"
ssh user@source-host "sudo blockdev --getsize64 /dev/sda"

The second command prints the source size in bytes. Keep it — it feeds pv -s later.

5The clone

A. dd built-in progress

ssh user@source-host "sudo dd if=/dev/sda bs=4M status=progress" \
  | sudo dd of=/dev/sdb bs=4M status=progress conv=fsync

B. pv bar with ETA

SRC_BYTES=$(ssh user@source-host "sudo blockdev --getsize64 /dev/sda")
ssh user@source-host "sudo dd if=/dev/sda bs=4M" \
  | pv -s "$SRC_BYTES" -b -t -r -e \
  | sudo dd of=/dev/sdb bs=4M conv=fsync

C. Compressed stream

SRC_BYTES=$(ssh user@source-host "sudo blockdev --getsize64 /dev/sda")
ssh user@source-host "sudo dd if=/dev/sda bs=4M | pigz -1" \
  | pv -s "$SRC_BYTES" -b -t -r -e \
  | pigz -d \
  | sudo dd of=/dev/sdb bs=4M conv=fsync

conv=fsync flushes to stable storage before dd returns.

6Monitor from another terminal
pgrep -a dd
sudo kill -USR1 
iostat -dx 2 /dev/sdb
7Verify the clone
ssh user@source-host "sudo dd if=/dev/sda bs=1M count=1" | sha256sum
sudo dd if=/dev/sdb bs=1M count=1 | sha256sum

SRC_BYTES=$(ssh user@source-host "sudo blockdev --getsize64 /dev/sda")
SKIP=$(( (SRC_BYTES / 1048576) - 1 ))
ssh user@source-host "sudo dd if=/dev/sda bs=1M skip=$SKIP count=1" | sha256sum
sudo dd if=/dev/sdb bs=1M skip=$SKIP count=1 | sha256sum

Full hash is the only definitive check.

8Sync and power off
sync
sudo udisksctl power-off -b /dev/sdb

If the source was bootable, boot the target machine from the USB disk to confirm.

Interactive walkthrough (Docker)

The panel below unlocks advanced operations when the local Docker backend is running: dry-run, compression, bandwidth limit, tolerate-read-errors, resume from offset, verify-after-clone, and optional remote destination.

Probing backend…

Backend is online. Paste the BACKEND_TOKEN from .env to continue.

Advanced operations

Remote destinations bypass the local device allowlist. You will be asked to type user@host:device verbatim as an extra confirmation step.

1Clone the repo and configure .env
git clone https://github.com/OWNER/remote-dd-clone-guide.git
cd remote-dd-clone-guide
cp .env.example .env
$EDITOR .env

Generate a token with openssl rand -hex 32. The allowlist must include the exact USB device path (e.g. /dev/sdb).

2Start the backend
docker compose up -d
docker compose logs -f backend

Wait for backend 1.0.0 listening on 0.0.0.0:8080 and the allowlist echoed. Reload this page — the badge turns green.

3Authenticate and dry-run

Paste the token. Fill in the form, open Advanced operations if you want them, then click Dry run. The exact command the backend would execute appears — no bytes are written.

4Clone

Click Start clone. For a local destination you type the device path to confirm; for a remote destination you type user@host:device. Progress is tracked via /sys/block/<dev>/stat. Abort kills the process group.

5Verify and power off
sync
sudo udisksctl power-off -b /dev/sdb

If you selected spot or full verify, the backend prints the comparison when the clone finishes. Power off cleanly before unplugging.

Safety guardrails

  1. Allowlist. The backend refuses any local destination not in ALLOWED_LOCAL_DEVICES. Empty by default.
  2. Typed confirmation. Local: type the device path. Remote: type user@host:device.
  3. Dry run. POST /dryrun returns the exact command without executing.
  4. Loopback bind. 127.0.0.1:8080; not reachable from the network.
  5. Input validation. Host, user, and /dev/* paths regex-gated.
  6. Unmount guard. Manual script refuses if target is mounted. Backend refuses if destination reports an active mount.
  7. Abort kills the process group. SIGTERM, then SIGKILL after 1 s.

The Docker container runs privileged. It writes to host block devices. Everything above is defence in depth, not a substitute for pointing of= at the right device.

dd command reference

CommandWhat it does
ssh user@host "sudo dd if=/dev/sda bs=4M status=progress"Reads the source over SSH, prints progress.
sudo dd of=/dev/sdb bs=4M conv=fsync status=progressWrites stdin, flushes to stable storage before returning.
pv -s SIZE -b -t -r -eProgress bar with bytes, elapsed, rate, ETA.
dd conv=noerror,syncOn read error, continue and pad the bad block with zeros.
dd skip=N seek=NSkip N blocks on source, seek N blocks on destination.
sudo kill -USR1 PIDAsk a running dd for stats without stopping.
blockdev --getsize64 /dev/sdaExact size in bytes; feeds pv -s.
pigz -1 / pigz -dParallel gzip compress / decompress. zstd and lz4 also supported.
